## Architecture: Smart Account Model

- **Customer**: 自分の Smart Account（`kit.createWallet` で passkey から作成）。自分の C-address にスタンプ／Beans／特典／バッジを保持。
- **HQ Smart Account**: 5 contracts 全ての admin。Staff の passkey は HQ SA の signer として登録。
- **3-Context-Rule の整合性（重要、踏みやすい罠）**: `issue()` は 3 回の `admin.require_auth` を発生させる（visit-stamps / beans-token / reward-policy）。OZ `__check_auth` は `AuthPayload.context_rule_ids` を **3 つの auth_contexts と index 整合** させる必要があり、staff passkey は **3 つの CallContract context rule** に登録する。1 ルールだと `SmartAccountError #3014 ContextRuleIdsLengthMismatch` で失敗。
- **Staff sign-in**: HQ root credential で `connectWallet`（staff credential で connect すると contractId が credential storage 由来に上書きされてしまう）。staff credential は `signAndSubmitTx(tx, { credentialId: staffCred, resolveContextRuleIds: () => [r_vs, r_beans, r_policy] })` で渡す。
- **OZ context-rule name max = 20 bytes**。

### Cross-contract flow（1 回の issue で発生）

```
visit-stamps.issue(admin=HQ-SA, to=customer-SA, venue)
  ├─ beans-token.mint(admin, to, 10)                       ← auto mint
  └─ reward-policy.on_stamp_issued(admin, to, new_count)   ← count を引数で渡す
       ├─ benefits.mint(...)   [count ≥ 10、claimed-guard で 1 回のみ]
       └─ badges.issue(...)    [count ≥ 100、同上]
```

**re-entry 禁止**: Soroban はコントラクト再入を許さないため、reward-policy は visit-stamps を call-back **しない**。stamp_count は引数で渡す。

### Error Handling 🟡

- **Rust contracts**: `assert!(...)` + context 文字列（例: `"already initialized"`）／enum `DicekeyError` で domain error
- **TypeScript SDK**: async/await、エラーは伝播（try-catch は呼び出し側）
- **React**: `ErrorBoundary` を `App.tsx` で wrap、Suspense と組み合わせ
- **axios (kit 経由)**: `"Network Error"` がそのまま浮上する（UX 改善は Phase 1 の派生課題）

### Import Order 🟡

- **TypeScript**: External (`@stellar/stellar-sdk`, `react`) → Internal (`@dicekey/sdk`, `@dicekey/contracts`) → Relative (`./config.js`, `./pages/...`)
- **Rust**: 標準 → `soroban-sdk` → `dicekey_shared` → 自 crate を `use` ブロックで区切る

### Comments 🟡

- Rust: `///` で public item に doc コメント、`// ──` をセクション区切りに
- TS: 意図ベースの `//` を最小限。自明な what は書かない
- 言語ポリシー: **コード／コメント／コミット = 英語**、**docs/ = 日本語可**、**会話的返答 = 日本語**

## Environment & Constraints

### localnet 構成 🔵

- ホスト名: `stellar-localnet:8000`（devcontainer 内、`localhost` ではない）
- Passphrase: `Standalone Network ; February 2017`
- `.devcontainer/devcontainer.json` `forwardPorts`: **`[5173, 5174, 8000]`**（**8443 は含まれない** → ホスト OS ブラウザから HTTPS proxy 不可達。Network Error バグの構成要因の 1 つ）
- `.devcontainer/Caddyfile.host` あり（運用案内が未整備）

### kit の運用要件 🔵

- **HTTPS RPC 必須**: localnet RPC は HTTP のため `scripts/rpc-https-proxy.mjs` でシム
- **Fee payer 固定鍵**: `GAAH4OT36RRCCAGKARGPN2HLHT2NOBVFHO4GUHA6CF7UKQ4MMV24WQ4N`（`packages/sdk` にハードコード）。localnet では friendbot 補充。**Phase 1.5 で Worker secret 化、固定鍵削除予定**
- **CDP headless Chromium が SIGSEGV することがある** → retry で対処

### One-Shot Pipeline の理由 🔵

`sa-setup.mjs` と E2E bootstrap は **その run の HQ SA で contracts を初期化** する。同じ contracts に対して再実行すると `already initialized` で trap（UnreachableCodeReached）。よって毎回 `deploy-localnet.sh`（新規 deploy）→ `generate-bindings.sh` → sa-harness restart → setup を 1 パスで通す。

### 既知の未対応 🔵

- `apps/staff-app` の Use Beans / Receive Benefit は最小実装 + TODO（beans は customer の `approve` 要、benefits は `burn_from` 未提供）
- ターゲット構造（CF Pages + Worker + Testnet）への移行は未着手
