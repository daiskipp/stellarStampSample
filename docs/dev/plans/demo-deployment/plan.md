# Plan: demo-deployment

> Lightweight mode / Last updated: 2026-05-22
> Generated by dev-plan based on `docs/dev/context.md` and `.dcs/20260522084831_passkey_signup_network_err/final_report.md`

## Requirements Summary

複数人が同時に触れるデモ環境を作る。`*.pages.dev` で公開し、Stellar **Testnet** に 5 contracts を deploy、最小 Hono Worker で fee payer の sequence を直列化することで `tx_bad_seq` 競合を防ぐ。

スコープは **Phase 1（公開）+ Phase 1.5（Worker 化）** の 2 段階。Phase 1 単体でも触れる状態にはなるが、複数人同時操作で sequence 競合が起きるリスクを受容する短期構成。

### 既に確定している方針（dev-plan ヒアリングで決定）

| トピック | 決定 |
|---------|------|
| HQ SA Testnet bootstrap | `scripts/sa-setup-testnet.mjs` を新規追加（既存 `sa-setup.mjs` は localnet 用で温存） |
| E2E (Playwright) | localnet 専用のまま。Testnet 向け smoke は本計画外 |
| CF Pages 公開範囲 | 公開 URL (`*.pages.dev`、誰でもアクセス可)。fee payer drain リスクは Phase 1.5 まで受容 |
| Worker sequence 採番 | **Durable Object** で一元管理（race-free） |

### 非ゴール（本計画から除外）

- OZ Relayer 正式統合（Phase 2 以降）
- KV/D1 等のオフチェーンデータ保存（Worker の sequence 採番 DO のみに限定）
- Biome/Just/Vitest などのツール整備
- localnet 開発フローの破壊（既存 `scripts/sa-setup.mjs` / `scripts/rpc-https-proxy.mjs` / E2E は維持）

## Design Overview

### Phase 1 アーキテクチャ

```
[ ホスト OS Chrome ]
        │ https
        ▼
https://localhost:5173      (Vite dev / customer-app, basicSsl で TLS 終端)
  └─ /rpc  ─ proxy ─▶  http://stellar-localnet:8000   (localnet 開発時)

[ 公開 Demo on CF Pages ]
  https://customer-app-xxx.pages.dev  ──┐
  https://staff-app-xxx.pages.dev    ──┤  https
                                       ▼
                          https://soroban-testnet.stellar.org   (SDF 公開 RPC、CORS OK)
                                       ▼
                          [ 5 dicekey contracts on Testnet, admin = HQ SA ]
```

### Phase 1.5 アーキテクチャ

```
[ ホスト Chrome ]
    │ https /rpc (kit 内部読み取り) + /relayer (kit が relayerUrl 経由で submit)
    ▼
   pages.dev (customer/staff)
    │ kit.signAndSubmit → relayerUrl 設定で自動切替
    ▼
  Workers (Hono on CF Workers)
    POST /relayer (kit 公式 protocol: {func, auth} or {xdr})
     ├─ Origin allowlist + Inner-tx contract id 検証
     ├─ SequenceManager DO に next seq 要求 (race-free)
     ├─ TransactionBuilder で外側 tx 構築 (sourceAccount = fee payer)
     ├─ fee payer secret で sign
     └─ rpc.sendTransaction → pollTransaction → { success, hash } を返却
    │
    └ Durable Object: SequenceManager (in-memory + RPC fallback resync)
```

### 重要インターフェース

#### Vite Proxy (Phase 1.A)

```typescript
// apps/customer-app/vite.config.ts (staff-app も同型)
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
import basicSsl from "@vitejs/plugin-basic-ssl";   // 🔵 新規依存

export default defineConfig({
  plugins: [react(), basicSsl()],
  server: {
    https: true,                                    // 🔵
    proxy: {
      "/rpc": {                                     // 🔵
        target: "http://stellar-localnet:8000",
        changeOrigin: true,
        secure: false,
      },
    },
  },
});
```

#### Testnet env (Phase 1.B)

`.env.testnet` (新規生成) を CF Pages の env vars に同期。`VITE_RP_ID` は CF Pages の実 host (`customer-app-xxx.pages.dev`) に合わせる必要があり、customer と staff で別 RP となる点を設計前提とする。🔴

#### Worker /relayer (Phase 1.5)

kit の公式 relayer protocol に準拠：

```typescript
// 受信
type RelayerRequest =
  | { func: string; auth: string[] }   // 通常 tx (kit 自動経路)
  | { xdr: string };                    // deployment / source_account auth tx

// 返却
interface RelayerResponse {
  success: boolean;
  hash?: string;
  status?: "SUCCESS" | "FAILED" | "PENDING";
  errorCode?: "INVALID_PARAMS" | "INVALID_XDR" | "SIMULATION_FAILED"
            | "ONCHAIN_FAILED" | "UNAUTHORIZED" | ...;
}
```

#### SDK 改修 (Phase 1.5)

`packages/sdk/src/smart-account.ts` の `createKit()` に `relayerUrl` を渡すだけ。`signAndSubmitTx` 本体は **無改修**。

```typescript
return new SmartAccountKit({
  ...,
  relayerUrl: cfg.relayerUrl,    // 🔵 env.VITE_WORKER_URL 未設定なら undefined → 従来通り rpc 直接
});
```

### 検証結果（Plan サブエージェントが Read 確認）

| 項目 | 結果 | 出典 |
|------|------|------|
| kit rpcUrl の絶対 URL 要求 | 必須（相対 NG） | `.oz-build/smart-account-kit/src/kit.ts:355,361,363` |
| fee payer 鍵の所在 | `packages/sdk` に **無し**、kit 内部で deterministic derive | `.oz-build/smart-account-kit/src/kit.ts:407-411`, `scripts/fund-localnet.mjs:49-51` |
| kit の relayer 機構 | あり (`relayerUrl` config + tx-ops.ts:62 で自動経路選択) | kit ソース確認済み |
| `deploy-testnet.sh` の問題 | wasm target が `wasm32-unknown-unknown`（NG）、`.env.testnet` テンプレ不完全 | `scripts/deploy-testnet.sh` |
| devcontainer forwardPorts | `[5173, 5174, 8000]`（8443 無し）= Vite proxy 案では問題なし | `.devcontainer/devcontainer.json` |

### 🔴 残課題（実装時に再確認）

1. **CF Pages の RP ID 制約**: customer-app と staff-app が別 sub-host になるため別 RP。HQ SA の signer を双方で enroll する必要があり、enroll の手順を Phase 1 のドキュメントに含める必要あり (Task 005/006/007)
2. **kit の relayer 経路で func は prepared かどうか**: Worker 側で `prepareTransaction` を呼ぶ必要があるかの確認が Task 010 で必要
3. **CF Pages builder で `scripts/build-kit.sh` が動くか**: OZ account spec を Testnet から fetch するため network 必要 (Task 006)
