## 既知の追加検証ポイント

**Multi-RP 制約** (Plan 🔴 残課題 #1):

- customer-app は `dicekey-customer-app.pages.dev`、staff-app は `dicekey-staff-app.pages.dev` で **RP host が異なる**
- WebAuthn の rpId は host に紐づくため、customer-app で作った passkey credential は staff-app では使えず、逆も同じ
- HQ SA に複数 RP の signer を addPasskey できるかは kit 0.3.0 の挙動次第。`docs/design/dicekey-coffee-stamps/smart-account-integration.md` の調査範囲外 → 実デプロイ後の動作検証で:
  - staff-app 側で「この端末を登録」フローを実行し、HQ SA に staff-app の RP で別 passkey 1 個を signer 追加
  - 既存 staff rule (`VITE_HQ_STAFF_RULE_IDS`) を流用するか、新規 rule を 3 + 1 作るかは kit の addPasskey API の挙動次第（runbook の検証フェーズで決まる）
