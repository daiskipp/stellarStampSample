## Requirements Summary

CF Pages 上にデプロイ済みの `staff-app` (`https://dicekey-coffee-stamps.pages.dev/staff/`)
で **実機 passkey から sign-in できる** 状態を作る。

現状の詰まり:

- `just testnet` の `scripts/sa-setup-testnet.mjs` は **devcontainer 内の CDP virtual
  authenticator** で HQ root passkey を作る。秘密鍵はその仮想 authenticator
  の中にしか存在せず、外部に取り出せない (WebAuthn の設計上の制約)。
- そのため CF Pages 上の staff-app から `enrollStaffDevice` (= `add_context_rule`
  txs を HQ root credential で署名する処理) が成立しない。実機の secure
  enclave に存在しない credentialId を `allowCredentials` に並べても WebAuthn
  prompt が返事を返せない。
- `kit.connectWallet({contractId, credentialId})` 自体は **on-chain 存在チェック
  のみで WebAuthn prompt を出さない** (`.oz-build/smart-account-kit/src/kit/
  wallet-ops.ts:246-261`)。つまり sign-in は技術的には通る。詰まるのは
  `signAuthEntry` を必要とする操作 (= staff の端末セットアップ、`Use Beans` 等)。

採用方針 (`/tsumiki:orchestrate` ヒアリングで決定 — 2026-05-27):

> **案 A: `just hq-setup-testnet` で実機ブートストラップ**
>
> 既存 `just hq-setup` (localnet 用、ホストブラウザの Touch ID / Windows Hello
> で HQ SA を作る UI ベースの recipe) の Testnet 版を新設する。HQ root passkey
> がホスト OS の secure enclave に常駐するため、同端末で開いた staff-app から
> `enrollStaffDevice` が成立する。

### `hq-setup-testnet` recipe の中身

`just hq-setup` の Testnet 版。違い:

| | `hq-setup` (localnet) | `hq-setup-testnet` (Testnet) |
|---|---|---|
| RPC | http localnet → HTTPS proxy 必須 | https Testnet RPC 直接 |
| `rpc-https-proxy.mjs` | 起動する (port 8443) | **起動しない** |
| `pnpm dev` mode | デフォルト (`.env` 読込) | `--mode testnet` (`.env.testnet` 読込) |
| 操作前提 | `just deploy-localnet` 済 | `just deploy-testnet` 済 |
| 不可逆性 | 何度でも fresh | **HQ SA は再作成のたび孤児化、5 contracts も再 deploy 必須** |
| 既存 hq-setup の `PROXY_HOST=0.0.0.0` | 必要 (ホストから dev container の proxy へ) | 不要 |

```just
# 🔴 HQ bootstrap UI for Stellar Testnet. UNLIKE `just hq-setup` (localnet),
#    this orphans the previous HQ Smart Account every run — the 5 dicekey
#    contracts must be freshly redeployed via `just deploy-testnet &&
#    just bindings-testnet` BEFORE invoking this recipe, otherwise the new
#    HQ will not be admin of those contracts. No rpc-https-proxy.mjs spawn:
#    Testnet RPC is already HTTPS, and harness branches on the localnet
#    passphrase to skip the proxy layer (tools/sa-harness/src/harness.ts:54-65).
[doc("Start the HQ setup UI for host-browser passkey-driven HQ on Testnet (IRREVERSIBLE)")]
hq-setup-testnet:
    #!/usr/bin/env bash
    set -euo pipefail
    echo "=== HQ-SETUP-TESTNET — IRREVERSIBLE. Creates a NEW HQ Smart Account."
    echo "    Old HQ (if any) becomes orphaned. Prereq: just deploy-testnet &&"
    echo "    just bindings-testnet ran. Ctrl-C within 5s to abort. ==="
    sleep 5
    echo "[just hq-setup-testnet] starting sa-harness --mode testnet on :5180…"
    echo "[just hq-setup-testnet] open http://localhost:5180/ in the host browser,"
    echo "                        then follow docs/dev/plans/hq-setup-testnet/runbook.md."
    pnpm --filter sa-harness dev --mode testnet
```

`just hq-setup` と違って proxy なし、5 秒 abort window 付きで不可逆性を周知。
port 5180 が host にも見える条件は Orbstack/Docker の port forwarding
(devcontainer 設定で既に 5180 は公開済み、`just hq-setup` で動作実績あり)。

### 実行フロー (runbook.md にも記載)

```
1. just deploy-testnet          # 5 contracts fresh deploy → .env.testnet 更新
2. just bindings-testnet        # TS bindings regen + @dicekey/contracts build
3. just hq-setup-testnet        # harness を Testnet モードで起動 (foreground)
   ↓
   ホストブラウザで http://localhost:5180/ を開く
   ↓ (UI 操作)
   a. createWallet("dicekey HQ", "hq-admin")
      → 実機 Touch ID / Windows Hello の prompt → 認証
      → contractId=<新 HQ SA> / credentialId=<新 HQ root cred>
   b. initializeDicekey(<新 HQ SA>)
      → 5 contracts に admin として init
   c. wireContracts(<新 HQ SA>)
      → visit-stamps↔beans, visit-stamps↔reward-policy を結線
   d. setupStaffRules(<visit-stamps>, "staff1")
      → 1 つ目の staff passkey + 3 CallContract rules (visit-stamps/beans/policy)
        + 1 benefits rule = 計 **4 rules** (harness.ts:setupStaffRules)
   ↓ harness Step 4 の env block (7 行) を「Copy」ボタンで一括コピー
4. .env.testnet を更新 (harness が出力する 7 キー):
     VITE_HQ_SMART_ACCOUNT
     VITE_HQ_ROOT_CREDENTIAL_ID
     VITE_HQ_STAFF_CONTEXT_RULE_ID
     VITE_HQ_STAFF_RULE_IDS
     VITE_HQ_STAFF_BENEFITS_RULE_ID
     VITE_HQ_STAFF_CREDENTIAL_ID
     VITE_HQ_STAFF_NAME
5. apps/customer-app/.env.production を .env.testnet と同期
6. apps/staff-app/.env.production を .env.testnet と同期
7. just pages                   # build-pages + deploy-pages
8. ホストブラウザで https://dicekey-coffee-stamps.pages.dev/staff/ を開く
   → 「端末セットアップ」を実行
   → 実機 Touch ID で HQ root cred prompt → 新 staff passkey 作成 → 4 つの
     add_context_rule tx 署名 (= 計 5 連発の WebAuthn assertion)
   → sign-in 成功
```

### sa-harness UI の改修が必要か?

**結論: 不要** (Plan エージェントが `tools/sa-harness/index.html` +
`harness.ts` を実機確認、2026-05-27)。

| 必要操作 | UI 露出 | 出力表示 |
|---|---|---|
| `createWallet` | Step 1 ボタン (`#btnCreateHq`) | `#resultHq` に contractId / credentialId |
| `initializeDicekey` + `wireContracts` | Step 2 ボタン (`#btnInitWire`、`checkInitialization` で fail-fast) | `#resultInitWire` に成功 or エラー hint |
| `setupStaffRules` | Step 3 ボタン (`#btnStaffRules`) — visit-stamps/beans/policy + **benefits** = **計 4 rules** を作成 | `#resultStaffRules` に ruleIds / benefitsRule / staffCred |
| env 一括出力 | Step 4 (`#envBlock` + `#btnCopyEnv`) | **7 行**の VITE_* env をクリップボードへ一括コピー |

Step 4 が出力する 7 キー: `VITE_HQ_SMART_ACCOUNT` /
`VITE_HQ_ROOT_CREDENTIAL_ID` / `VITE_HQ_STAFF_CONTEXT_RULE_ID` /
`VITE_HQ_STAFF_RULE_IDS` / `VITE_HQ_STAFF_BENEFITS_RULE_ID` /
`VITE_HQ_STAFF_CREDENTIAL_ID` / `VITE_HQ_STAFF_NAME`。runbook は
**7 キーすべて**を貼り先 (`.env.testnet` + `apps/*/.env.production`)
に伝播する手順で書く。

### 失敗時のロールバック

HQ 再作成は不可逆 (古い HQ は孤児化) なので、進める前に:

- `.env.testnet` を `.env.testnet.bak.YYYYMMDD` として手動コピーバックアップ
- `dist-pages/` は git untracked なので削除しても問題なし

失敗ケース:

| 症状 | 対応 |
|---|---|
| harness UI で `createWallet` が WebAuthn prompt を出さない | hostname が `localhost` か確認 (`127.0.0.1` は別 origin)。Chrome 限定 (Safari は localhost で WebAuthn 不可) |
| `initializeDicekey` で `already initialized` trap | 5 contracts を `just deploy-testnet` で fresh にし直す |
| CF Pages 上で `Smart account contract not found on-chain` | `VITE_HQ_SMART_ACCOUNT` が古い HQ を指している。`.env.production` の値を再確認 |
| 実機 sign-in で WebAuthn prompt が出ない | RP_ID 不一致。`VITE_RP_ID=dicekey-coffee-stamps.pages.dev` を確認、ホストの URL が完全一致しているか |
